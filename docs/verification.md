# Verification

What proves that the derivatives are right, how to run those checks, and what was checked on this code.
Section 6 lists the state of every check; read it before quoting anything on this page.

The adjoint of every turbulence and transition model in this fork is generated by Tapenade; there is no
hand-written derivative of the model equations. The hand-written part is the wiring (which routine is
called in which sweep), see [developer.md](developer.md).

## 1. The derivative ladder

All derivative tests linearise about a stored state on the standard ADflow tutorial wing (Mach 0.15,
α 1.8°). The steps are ordered from cheap to expensive; each one isolates a different kind of error.

| Step | Check                                                       | Build   | What it proves                                                                                                                         | What it cannot see                         |
| ---- | ----------------------------------------------------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 0    | Blockette residual = block residual (GR)                    | real    | The cache-blocked residual kernels compute the same residual as the reference block routine for the same state                         | Anything about derivatives                 |
| 1    | Dot product, forward against reverse: ⟨ψ, J·ẇ⟩ = ⟨Jᵀ·ψ, ẇ⟩  | real    | Forward (`_d`) and reverse (`_b`) code are transposes of each other, per coupling block                                                | An error present identically in both modes |
| 2    | Reverse (`_b`) against fast reverse (`_fast_b`)             | real    | The post-processing that produces the state-only fast reverse code did not drop a value it needed; seeded one equation block at a time | An error in the linearisation itself       |
| 3a   | Forward AD against stored references and finite differences | real    | Regression against trained reference values. The finite-difference comparison is context only (see below)                              | —                                          |
| 3b   | Forward AD against complex step, partial derivatives        | complex | The linearisation is the derivative of the residual: ∂R/∂w for all 16 coupling blocks, ∂R/∂x (mesh), ∂R/∂(α, Mach, P, T)               | Solver convergence effects                 |
| 4    | Total derivatives by the adjoint                            | real    | The assembled adjoint gives df/dx for cl, cd, cmz with respect to α, Mach, twist, span and shape variables; compared with references   | —                                          |
| 5    | Total derivatives by complex step                           | complex | The adjoint totals equal the totals of a complex solve re-converged for each design variable                                           | —                                          |

Steps 0–3b evaluate matrix–vector products at the stored state and take seconds to minutes. Steps 4–5
converge real and complex solves and are the expensive part; they can fail for solver reasons (convergence
floor) with exact partial derivatives. Validated partial derivatives are not a validated gradient.

### Rules of the test suite

| Rule                                                                               | Reason                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The finite-difference residual tests are marked expected failure                   | The transition residual spans about 13 orders of magnitude; element-wise finite differences cannot meet a tolerance at any step (cancellation on near-zero cells). The test sweeps the step and reports the best one. Complex step is the enforced reference. An unexpected success means the marker should be removed; tolerances are never loosened to force a pass. |
| The complex-step block tests re-seat the real state before each column             | Consecutive complex-step calls share a work buffer; without the re-seat an imaginary residue of about 2e-8 appears in the structurally zero mean-flow rows of the next column.                                                                                                                                                                                         |
| The complex solves use the finite-difference preconditioner, segregated turbulence | The complex build has no AD preconditioner. The complex re-converge stalls near 1e-8, so the total-derivative comparison uses relative and absolute tolerances of 5e-8; Mach and `drag` are reported, not asserted (the Mach complex solve does not settle; `drag` duplicates cd).                                                                                     |
| Run the complex step with the rank count used to train the references              | A different partition linearises about a slightly different discrete state (about 1e-10).                                                                                                                                                                                                                                                                              |
| Stored states and references belong together                                       | After any change to differentiated code: regenerate the Tapenade code, rebuild real and complex, reinstall, retrain the references, then run the ladder.                                                                                                                                                                                                               |

### Reading a failure

| Symptom                                                       | Look at                                                                                                        |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Step 0 fails                                                  | The blockette kernel (maintained by hand in `blockette.F90`) has drifted from the model file                   |
| Step 1 fails                                                  | Forward / reverse wiring: Tapenade routine list, dispatch in `masterRoutines.F90`                              |
| Step 2 fails on transition-row seeds only                     | An active variable overwritten in place (see the Tapenade traps in [developer.md](developer.md))               |
| Step 3b fails, steps 1–2 pass                                 | Generated code out of date with respect to the source, or an active input missing from a Tapenade routine head |
| Step 3b fails on the transition rows of ∂R/∂(Mach, P, T) only | `uInf` / `muInf` not declared as inputs of the source routine (vorticity-limiter path)                         |
| Finite differences fail, complex step passes                  | Finite-difference noise, not an AD error                                                                       |
| Steps 4–5 fail, step 3b passes                                | Convergence depth of the primal or adjoint solve, or the floor of the complex re-converge                      |
| SA-BCM: one of the two forms fails                            | The branch selected by `SABCMSmooth`                                                                           |

## 2. Running the tests

The tests are testflo suites in `tests/reg_tests/`. They are being reorganised: **the exact file names and
commands are in `tests/reg_tests/README_transition.md`**; this section describes them by purpose and may
lag behind that file.

| Model  | What exists                                                                                                                                                                                                                                                                                                                                                    |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GR     | A configuration module (mesh, stored state, flow condition, options, helpers that split a vector into mean-flow / ν̃ / γ / R̅eθt blocks, assert helpers); forward-product tests (references, finite differences, complex step); reverse / fast-reverse and dot-product tests; adjoint totals against references and against complex step; blockette test         |
| SA-γ   | The same set without the blockette test (the blockette path is switched off for this model)                                                                                                                                                                                                                                                                    |
| SA-BCM | Forward and reverse product tests, run for the smooth and the original form at two states (the turbulent SA solution, and the same solution with ν̃ scaled by 0.01 and Tu 2 % so that Term1 is active): residual and forward products against references and against complex step, reverse dot product. No total-derivative test and no stored state of its own |

A convenience driver in the same folder wraps the testflo commands. It takes the model and a stage:

| Stage                          | Runs                                           | Build   | Cost                                                     |
| ------------------------------ | ---------------------------------------------- | ------- | -------------------------------------------------------- |
| fixed state, real              | steps 1, 2, 3a (and step 0 for GR)             | real    | minutes; workstation                                     |
| fixed state, complex step      | step 3b                                        | complex | minutes; workstation                                     |
| retrain fixed-state references | rewrites the reference JSON files              | real    | minutes                                                  |
| adjoint totals                 | step 4                                         | real    | solves the adjoint; cluster                              |
| adjoint totals by complex step | step 5                                         | complex | one converged complex solve per design variable; cluster |
| retrain adjoint reference      | rewrites the adjoint reference                 | real    | cluster                                                  |
| regenerate the stored state    | converges the flow and writes the restart file | real    | cluster                                                  |

Practical points:

| Point                        | Detail                                                                                                                                                                                     |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Stored states are not in git | The restart CGNS files of the GR and SA-γ suites are not tracked and have no download server. A fresh checkout must regenerate the state first, then retrain the references.               |
| Installed package            | The tests import `adflow` from the installed package, not from the source tree. Reinstall after every rebuild; the banner at the top of the log shows what is installed.                   |
| Complex build                | Must be compiled against a complex PETSc architecture; object and module files of a real-architecture attempt must be removed first (`src_cs/` is not tracked, so `git clean` needs `-x`). |
| One thread per rank          | `OMP_NUM_THREADS=1`.                                                                                                                                                                       |
| Single test                  | `testflo <file>.py:<Class>.<test>`; `testflo --dryrun` lists the names.                                                                                                                    |

The crossflow term is covered at fixed state: the GR suites run a second parameter set
(`sagr_crossflow_tut_wing`, `transitionCrossflow=True`) about the same stored state, where the term is active
(it changes the R̅eθt rows of the Jacobian). Not covered by the standing suites: total derivatives with
crossflow (the stored state was converged without it) and rotating frames.

## 4. Plain SA against upstream

Residual, derivative products and a few solver iterations of this code compared with a build of upstream
`main` (revision 9638c0f5, clean tree) on the tutorial wing. With strict IEEE arithmetic in both builds the two
are identical in every value; with the production (fast-math) builds:

| Case                                                       | Largest relative difference | Note                  |
| ---------------------------------------------------------- | --------------------------: | --------------------- |
| Fixed state: residual, forward and reverse products        |                     1.8e-16 | every recorded number |
| After 5 ANK iterations: state, residual, cl, cd, cmz, drag |                     6.5e-14 | drag included         |

With `turbulenceModel="SA"` and `useSABCM=False` the fork therefore behaves as upstream on this case.
The comparison covers the scalar-dissipation tutorial wing with segregated ANK; other paths (multigrid,
overset, time-spectral, coupled ANK, NK) were not compared. The one deliberate difference in coupled
ANK is described in [developer.md](developer.md).

## 5. Smoke runs of the examples against the cluster runs

`examples/transition/smoke_all.sh` runs every example for 2 iterations from free stream on 6 ranks and
`smoke_compare.py` compares each log with the first iterations of the cluster run of the same case.
Report: `showcase/smoke_runs/SMOKE_REPORT.md` (run of 2026-11-13 with the final code, installed from a clean tree;
30 of 30 cases without error).

| Item                               | Result                                                                                                                                                                                                                |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cases run                          | 30 (15 airfoil, 2 swept wing, sickle wing, 4 AR5 wing, 8 optimisation set-ups with the baseline solve only); 64 800 to 4.40 M cells                                                                                   |
| Cases with a cluster twin          | 29 (the 3D optimisation set-up was run on a coarser mesh of the same family, for which no cluster run exists)                                                                                                         |
| Iteration 0 (free-stream residual) | 29 of 29 agree: total residual to between 0 and 3.3e-12 (most to 1e-14), cl and cd to 1e-15 where the cluster log prints them                                                                                         |
| Largest iteration-0 difference     | 3.3e-12, AR5 wing with SA-BCM: the cluster run went through a zero-deformation mesh warp, the example reads the mesh directly; the optimisation example, which warps the mesh as the cluster run did, agrees to 9e-15 |
| Iterations 1 and 2                 | agree to 5e-5 … 1e-3 and 2e-4 … 3e-2: the rank count differs (per-rank preconditioner, inexact linear solves). The differences are the same for GR, SA-γ and SA-BCM on one mesh and change with the local rank count  |
| Not run                            | 13.68 M-cell optimisation mesh and 7.42 M-cell AR5 mesh (too large for the workstation)                                                                                                                               |
| Cluster builds on the other side   | seven different revisions of the development branches                                                                                                                                                                 |

What this shows: for the three models, plain SA, scalar and matrix dissipation, crossflow, the periodic
mesh and the FFD-embedded meshes, the cleaned branch evaluates the same free-stream residual as the builds
that produced the results in [validation.md](validation.md), and the example scripts set up the same
problem as the cluster runs. What it does not show: anything below a residual reduction of one order —
no switch level of the ladders is reached in two iterations, and optimiser iterations, adjoint solves,
restarts and the NK phase are not exercised. It was not possible to separate the rank-count effect from a
code effect at iterations 1–2 by running the cluster rank count locally.

The run was first made on 2026-11-12 with an earlier build of the cleaned branch and repeated on 2026-11-13
with the final code on the same 6 ranks: the iteration rows of all 30 cases are identical in every printed
digit between the two runs (logs of the first run in `showcase/smoke_runs/previous_build_2026-11-12/`).
