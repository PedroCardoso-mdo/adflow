# CLAUDE.md — ADflow SA-BCM Differentiable Transition Model

## Goal

Finish revalidating the **differentiable reformulation of the SA-BCM (Bas–Cakmakcioglu–Mura)
one-equation transition model** for discrete-adjoint aerodynamic optimization in ADflow,
per Cardoso, Marta & Martins, *"Differentiable Reformulation of the SA-BCM Transition Model
for Adjoint-Based Aerodynamic Optimization"* (unpublished manuscript,
`docs/papers/SA-BCM_Differentiable_Reformulation.md`), which reformulates the original SA-BC /
SA-BCM model of Mura & Cakmakcioglu, AIAA AVIATION 2020-2714
(`docs/papers/SA-BCM_Transitional_Model.md`).

**The manuscript's own caveat is the reason this branch exists:** *"A bug has been identified
in the implementation underlying this manuscript. All adjoint-based sensitivity results must be
revalidated"* (Sec. 3.4, Figs. 10–11, and by extension the optimization results in Sec. 4).
The task of this branch is exactly that revalidation — verifying `computeJacobianVectorProductFwd`,
`computeJacobianVectorProductBwd`/`BwdFast`, and the total adjoint sensitivities against
finite-difference and complex-step, per the harness in `tests/reg_tests/*_bcm.py`.

Solver paths that must remain runtime-selectable and runnable with `use_SABCM=True`: decoupled
DADI/ANK turbulence solve, coupled/segregated ANK, and NK (the manuscript's hybrid ANK→NK
strategy, Sec. 3.1) — all exercised through the same `saSource` code path in `sa.F90` and its
`blockette.F90` mirror.

**Definition of done for any task: code compiles, smoke test runs N iterations without NaN.**
Physics correctness (matching the manuscript's validation results) is verified by the user at
the end, not task-by-task.

## Per-Task Workflow

1. Read `docs/current-task.md` for the active task and its `Context:` file list.
2. Load only those files (rule 8).
3. Implement, compile (`cd build && make -j`), run the smoke test.
4. On completion, write a `docs/task-log/<date>-<slug>.md` entry, add it to
   `docs/task-log/README.md`'s index, and reset `docs/current-task.md` for the next task.

## Hard Rules

1. **One task per session.**
2. **`sa.F90` / `blockette.F90` edit scope is restricted to the `use_SABCM`-gated code.**
   SA-BCM is *not* a separate file — it is hand-edited directly into `saSource`
   (`src/turbulence/sa.F90:294-413`) and its non-Tapenade ANK/blockette mirror
   (`src/NKSolver/blockette.F90:1004-1250`), guarded by `if (use_SABCM) then`. Only code inside
   those guarded blocks (the `tTgamma`/`γ` computation, the `ft2` override, and the
   `dtTgamma`-derived Jacobian terms folded into `qq`) is the sanctioned edit zone. Everything
   else in `sa.F90` — the unguarded SA production/destruction terms, `ft2` for plain SA
   (`use_SABCM=False`), diffusion, and any other model's shared code paths — must stay
   byte-identical to plain SA. (Note: an earlier project memory said "never touch sa.F90" —
   that applied to a different branch where the transition model lived in its own file. On
   `sa-bcm` the model is unavoidably inline in `sa.F90`, so the rule is scoped to the guard
   above instead.)
3. Skip multigrid / time-spectral / non-RANS-SA-specific paths until the RANS-SA case with
   `use_SABCM=True` is fully revalidated.
4. **All SA-BCM diagnostics go to the volume CGNS** via the existing `Tgamma(i,j,k)` block
   array (`src/modules/block.F90:515`, `src/modules/blockPointers.F90:124`) — this already
   exists, do not add a parallel debug mechanism. No new ASCII debug files, no per-cell
   printouts.
5. **Smoothing constants are not free to retune inside a task.** `SABCM_fsmooth=0.08`,
   `SABCM_S0_tanh=0.5`, `SABCM_maxsmooth=50.0` (the KS aggregation parameter ρ) are calibrated
   in the manuscript (Sec. 2, Eqs. 8–10) to preserve the baseline SA-BCM solution while bounding
   derivatives. Changing them is a physics decision, not a bug fix — flag it, don't just do it.
6. **Adjoint linearization is frozen** at this stage relative to the hand-written `sa.F90`.
   Tapenade-generated files are produced by Tapenade and must **never** be hand-edited — they
   are regenerated by rerunning Tapenade, not by manual edits. This covers
   `src/adjoint/{outputForward,outputReverse,outputReverseFast}/` (the `_d`, `_b`, `_fast_b`
   files, header `generated by tapenade`) and the raw intermediates
   `src/adjoint/{temp_forward,temp_reverse,temp_reverse_fast}/`. `.claude/settings.json`
   **prompts** on any Edit/Write to these dirs (Step 4); only proceed when the user explicitly
   authorizes a manual edit — in practice that means "I reran Tapenade, sync the tree."
   Hand-written adjoint code (top-level `adjoint*.F90`, `masterRoutines.F90`, `fortranPC.F90`,
   `autoEdit/*.py`, `Makefile_tapenade`) is not restricted. As of `85f40a0b` on this branch,
   `sa_d.f90`/`sa_b.f90`/`sa_fast_b.f90` are in sync with `sa.F90` (verified by empty
   `git diff` against the commit that introduced both together) — if you hand-edit `sa.F90`'s
   `use_SABCM` block, Tapenade must be rerun before any adjoint/AD test is trusted again.
7. **Compile + run = done.** Do not attempt physics verification yourself beyond the
   derivative-consistency ladder in `tests/reg_tests/README_BCM.md`. Do not interpret results
   beyond pass/fail. Do not "improve" beyond the task spec.
8. **Do not load files outside the task block's `Context:` list.** Token discipline matters —
   every task block is self-contained for a reason.
9. **Paper wins** when paper and code disagree. Source of truth:
   `docs/papers/SA-BCM_Differentiable_Reformulation.md` (the smoothed/differentiable model —
   this is what the code should implement) and `docs/papers/SA-BCM_Transitional_Model.md` (the
   underlying SA-BC/SA-BCM model being reformulated, for the non-smoothed `SABCM_Exp=True`
   path). Full paper text, not a distilled summary — do not create or rely on distilled physics
   summaries (see the retired-doc lesson in `docs/README.md`; learn it up front instead of
   relearning it after several transcription errors).
10. **Units are p-ρ non-dimensional, not velocity-based** (ADflow-wide convention). SA-BCM's
    `Rv = ρ d² S / μ` (manuscript Eq. 5) and the eddy-viscosity ratio in `term2` both mix
    velocity-scale (`S`, vorticity) and viscosity-ratio quantities — check
    `docs/nondimensionalization.md` before touching either term.
